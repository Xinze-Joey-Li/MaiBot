# QQ-Agent 聊天标签修复与离线验收

日期：2026-10-16。修改基于工作区已有整合结果，保留其他未提交改动。未提交、推送、启动机器人或发送 QQ 消息；未调用真实模型。

## 1. 运行基线与确认范围

重新读取这次运行对应的三个 JSONL 文件，确认全部模型调用 630 次、2,617,965 Token；提取 46 次、125,377 Token；冲突 208 次、1,061,779 Token（输入 1,058,965、输出 2,814）。标签合计 1,187,156 Token。冲突平均每次总用量 5,104.7 Token。这些都是旧运行的已上报用量，不代表修复后的运行。

原实现每个新标签分别比较同分类最多 20 个旧标签。冲突载荷包含旧标签整行记录、来源引文，以及新标签的完整 dataclass；同一组旧标签可能随多个新标签反复发送。冲突请求本身没有附带完整聊天历史；主要是标签定义、证据和数据库管理字段的重复。历史原始请求未完整保存，不能把某个字段的字符比例直接当作实际 Token 占比。

## 2. 确认的问题与未确认的历史根因

- 原 `_process_job` 每次执行重新调用 `get_batch_context`，再按 `previous_batch_id` 取有效标签。任务只保存上一批 ID，没有保存标签内容、状态和 Prompt 依据；人工编辑、状态变化后重试可看到不同数据。
- 同一次请求中 Prompt 的 `previous_extraction_tags` 和解析器来自同一个列表，使用的都是标签数据库字符串 ID。没有发现代码把它转换为批次序号、任务 ID 或消息 ID。
- 原 Prompt 的 `previous_batches` 还暴露更早标签的 ID，但这些 ID 不在允许引用集合；这是模型误引用的可能来源，不能从现存证据确认模型当时是否因此出错。
- 原结构错误重试只有通用异常，新请求没有附带无效 ID 和允许集合。因此错误会在同一任务上多次无针对性重试。
- 原代码已有同会话租约、五次失败隔离、人工恢复入口、已验证输出缓存、冲突分块缓存、成功提交才消费收件箱、幂等批次和公平调度。本次保留并验证这些机制。
- 未保留三个失败任务每次原始模型输出及原始完整 Prompt，因此无法确定它们具体输出了哪个错误 ID，也不能把并发认定为历史唯一根因。新代码会持久化具体错误诊断和引用快照。

## 3. 实际修改

### 引用与恢复

`tag_memory_store.next_extraction_job` 在创建任务的 SQLite 事务内冻结 `reference_snapshot`、`snapshot_id`、`previous_batch_id` 和 `snapshot_origin`。旧前文仅保留解释所需摘要和无 ID 标签；允许集合只来自紧邻上一次提取的标签 ID。

`TagExtractionService._process_job` 始终使用相同冻结消息、标签及提取模板。初次生成后最多两次结构修复，请求附带具体校验错误、允许引用集合和上一批 ID；不静默删除引用，也不允许任意历史引用。总共三次服务层生成机会跨任务重试持久化；网络异常或进程中断已发出的机会也计入上限，以约束未知重复费用。耗尽则立即进入可查询 `failed` 状态；其它服务故障保留原有五次任务失败上限。

人工恢复保持消息、job_id 和快照，重新开放生成机会，并记录 `recovery_requested`。旧任务在首次恢复时补冻当前可用上下文，明确标记 `legacy_first_resume`；不能声称重建了当时的原始快照。

提交仍在一个事务中完成标签、来源、冲突、批次、消费确认和新增提交审计。解析失败、缺少冲突结果、版本变化或数据库回滚均不消费消息。提交时额外核对同分类候选集合，检查期间人工新增相关标签也会要求重算。重复批次仍由外部 ID 与指纹保证幂等。

### 冲突成本

- 完全相同的模型标签条目去重；同一旧标签 ID 重复输入归一化，不同内容同 ID 则报错。
- 仅对名称/摘要和来源 ID、逐字证据完全相同且有效的标签对本地判为重复。相似措辞、包含关系和日期差异均不能在本地代替语义判断。
- 筛选保持同会话、同人物/群公共及同分类；词汇交集只影响顺序，不排除低相似候选。未引入按关键词或日期截断的新召回门槛。这样保留改名、同义表达、偏好变化的检查机会，但同分类历史很多时成本仍会增长。
- 多个新标签共享旧标签定义，一次最多 40 个显式标签对、动态数据序列化检查上限 24,000 字符。每对用短 `candidate_id` 关联，内部全长摘要用于缓存键；禁止缺项当作无冲突，需显式 `coexist`。
- 部分结果缺失时先缓存有效项，下一轮只请求未完成项；格式错误保留纠错诊断。收到的原始响应先写文件检查点，数据库用量写入失败不重复模型请求。
- 跨任务的定向标签对缓存包含会话、内容、来源、时间信息、旧标签状态/修订、规则版本和模板内容；不对新旧顺序做对称归一化。缓存有效期 14 天。整体任务裁决缓存也校验规则版本；变化后重新计算。
- 固定说明放前面、共享旧标签定义在动态数据前部；移除不参与判断的保留/活跃等存储字段。中、英、日模板同步。

### 可观测性

新增 SQLite `extraction_events` 与 `conflict_pair_cache`，标签库版本 8 → 9。新增认证保护的同步路由：

`GET /api/webui/tag-memory/{session_id}/extraction-jobs/{job_id}/trace`

返回任务状态、错误、消息是否已消费、批次 ID、事件、恢复入口、请求返回用量及累计耗时。记录输入消息 ID/时间范围、上一批及允许 ID、快照哈希、提取尝试、候选/本地重复/缓存/模型数量、新增/延续/失效/争议数量。

`model_usage` 是单次服务调用返回的用量，用请求 ID 去重；`attempt_finished.cumulative_usage` 是累计快照，不能与单次用量再相加。失败的生成调用无用量时保留 unknown 计数；底层 Provider 尝试 ID/状态保留在用量事件中，较早尝试没有单独用量时列为 `unmeasured_provider_attempt_ids`，不假定为零。现有 Decision Replay 仍记录与该 job 关联的实际 Provider 请求事件。没有供应商上报的失败计费仍需供应商账单确认。
