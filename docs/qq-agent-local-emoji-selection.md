# 本地表情对象选择

原有双层发送概率先判断，群冷却仍由发送服务执行。只有概率命中后，本地挑选当前情绪 Tag 对应的对象；不会请求模型评分、识图或额外抽发送概率。一个候选直接选用；多个候选取惩罚后最高分，低于 70 不发送。

评分：情绪 Tag 精确命中 55；语境关键词覆盖率乘 25；useWhen 场景关键词覆盖率乘 15；标签、描述、关键词和场景字段完整得 2.5，加人工图片质量 quality×2.5，总分最高 100。匹配采用本地忽略大小写的字串命中，不是语义模型。语境使用回复目标文字和本次发送文字。缺少关键词或场景时该项为零；不虚构图片质量。

现有表情数据库没有 useWhen/quality。可在 `data/emoji_selection_metadata.json` 按 file_hash 填入元数据，格式见 `docs/emoji-selection-metadata.example.json`。keywords 与 useWhen 建议使用能在自然对话中出现的短关键词；useWhen 可为字符串列表或逗号、分号分隔文本；quality 为人工设定的 0—1 质量分。文件修改后下次评分直接生效，无需 API。未填写元数据的多候选只有情绪项，无法达到 70；单候选豁免。例子不是已经评估过的真实表情，不能当作生产元数据。

2026-10-15 已导入用户桌面“新建文件夹”的 148 个表情 Tag 记录，六个压缩包中的文件 SHA256 和大小全部校验通过。当前 32 个已注册表情中 30 个匹配。keywords 使用来源 Tags；useWhen 使用第三个 Tag，按包内“核心情绪/语义、动作、场景、补充特征”的近似顺序导入，属于词法场景提示而非另行人工确认的场景描述。来源未提供质量评分；随后按用户明确要求，这批 148 张表情的 quality 统一设为 1.0，属于用户指定值。完整词法匹配、元数据完整且无惩罚时最高 100 分。sourceTags/sourceFile 保留追溯信息，不改动现有注册标签。详情见 emoji-metadata-import-2026-10-15.json。未将剩余未注册图片批量导入表情库。

发送历史保存于 `data/emoji_selection_history.db`，按真实 session_id 隔离。所有经发送服务且平台确认成功的表情（包括暖群和独立 @）计入同群对象重复惩罚，但不会因此改变这些机制的群冷却豁免。失败发送不计入。

时间惩罚为 14×(1−距最后发送秒数/3600)。频率惩罚仅计最后一次之前的重复记录，每次贡献 2×(1−距该次发送秒数/3600)，总计最多 6。只参考最近一小时记录；恰满一小时贡献归零。每个记录线性衰减，封顶区间内总分可能保持在上限。只有一条历史不额外计频率惩罚。

保留最高分及同分时按哈希稳定选择；逐候选记录四项得分、两项惩罚和总分。数据库和元数据文件工作在线程中执行；异步发送异常单独记录，已发送文字不会重发。
