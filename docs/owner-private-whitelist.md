# 主人私聊添加接入白名单

基于9af882f6c的独立增量，分支codex/owner-private-whitelist。复用原E03、PermissionGuard、确认机制及AdapterPolicyManager，不创建新权限系统。

## 用法

仅已认证主人在QQ私聊中发送：

```text
/dfy access allow group 123456789
/dfy access allow private 234567890
```

先返回目标、Bot账号及适配器预览，再在同一主人私聊五分钟内发送 `/dfy confirm <令牌>`。群内不能添加或确认；普通用户即便已在接入白名单中，也没有管理权限。

有限中文入口支持 `管理：添加群聊白名单 123456789` 和 `管理：添加私聊白名单 234567890`，同样进入原E03预览确认。

也支持无需“管理：”前缀的完整句式，例如 `添加群聊1234567890进入白名单`、`添加账号1234567890进白名单`。账号/QQ号按私聊目标处理；可带“请”“帮我”或“大肥鱼，”称呼。号码必须明确，不能用昵称、多个号码或“跳过确认”尾句来执行；仍仅主人私聊有效，先预览再确认。这是受控句式解析，不是任意模糊意图执行。

旧 `/dfy access allow <群ID>`、deny/reset及list保持原行为。新增显式语法允许尚无历史会话的目标，不创建虚构聊天流或计算fallback归属ID。允许的是消息接入，不会自动加群、加好友、授予管理权限或修改QQ平台自身隐私设置。access list仍列举已知历史聊天流，不是所有未产生会话的策略条目清单。

## 安全与生效

- 原Guard要求可信QQ主人、已验证Bot、私聊、匹配的会话/目标；业务入口再次检查私聊和主人身份，写入前再检查主人是否被撤销。
- 通过当前主人私聊的真实会话，解析当前账号唯一接收适配器；无归属、多适配器、路由消失时拒绝，交由本地管理。
- 预览冻结完整AdapterIdentity及策略摘要；确认绑定主人platform/Bot/user/session、目标类型/ID和参数摘要，身份、路由或策略变化后必须重新预览。令牌一次有效，重启失效。
- 只新增精确适配器/账号下该目标的allow覆盖，原全局默认、其他群/用户和主人控制通道保持不变；不提供私聊deny/reset操作。不能通过放行重新启用已禁用适配器。
- 写入复用WebUI同一锁和原子策略文件，检查实际策略结果；文件/路由查询及写入均在线程，不占用主事件循环。策略求值每次读取文件，无需重启；不代表当前生产实例已经部署此增量。
- 新增chat_type/target_id审计摘要，预览、确认、拒绝及执行结果沿用原审计。重复添加不重复名单ID，进程重启后规则仍持久存在。
