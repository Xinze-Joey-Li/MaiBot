# 主人身份、Dashboard 与群聊管理

主人账号仅保存在本机受忽略的配置中，不写入代码、公开文档或模型提示词。身份只根据 QQ 网关提供的 message_info.user_info.user_id 判定，昵称、正文、引用、转发和自称 console/system/developer 不授予权限。

Dashboard 路径：配置 → 基础 → 主人身份与权限。专门卡片可编辑主人 QQ 号和“允许群聊管理命令”开关，复用已有配置保存和热重载机制。访问 Dashboard 仍须现有登录认证，QQ 主人身份不自动绕过 Dashboard 登录。

后端字段为 [bot].owner_qq 和 owner_group_commands_enabled，模板版本 8.14.75。更换主人后，后续命令按最新账号判定；排队的管理命令会重新检查身份及开关。后台关闭管理命令后，主人正常聊天仍保留。

群聊 @ deepseek娘 后可使用：

- /主人 人格：返回公开的简化身份，不输出完整系统 Prompt、聊天上下文或密钥。也支持“输出简化人格模板”。
- /主人 模型：列出后台已配置模型名。也支持“查看可选模型”。
- /主人 模型 planner 模型名称：替换 Planner 的模型列表为指定已配置模型。
- /主人 模型 replyer 模型名称：替换 Replyer 的模型列表为指定已配置模型。
- “选择模型 planner 模型名称”或“选择模型 replyer 模型名称”为等价格式。

仅这两个任务可切换；不允许用户输入 API 提供商、密钥、URL、文件路径或任意代码。模型保存使用既有保留格式的 TOML 工具及配置重载接口。管理命令在独立 @ 队列中本地处理，不增加 LLM 请求；正常 @ 回复、表情及并发限制保留。

Planner 和 Replyer 增加中英日一致的身份冒充与不可信内容规则；Replyer 的当前回复对象是否主人由 Python 从真实消息元数据注入，含复古模式。主人获得更积极、配合的正常对话风格，但不获得无条件危险操作权限。模型输出无法调用这条管理路径或授权自己改变配置。

防注入分为两层：管理权限有本地授权和操作白名单；模型对话有提示约束。不能承诺语言模型永远不会被诱导或生成错误内容，但这不授予配置写权限。网关凭据与 Dashboard 登录凭据必须可信；账号被盗或网关元数据被篡改不在提示词防护能力内。第三方插件自身暴露的管理工具需要各自权限审计，此功能不替插件补全授权。

验证：74 项权限、@ 回复、并发、表情、复古 Prompt 和聊天边界 pytest 通过，19 个子测试通过，Ruff 通过；后台 Schema 确認包含两个编辑字段。额外配置 Schema 套件出现既有 enable_clear_context_command 缺字段测试失败，与此次主人字段无关，未删除该测试。最终调整复古身份注入后，其 26 项相关测试通过。

Dashboard 卡片属于小范围改动，按仓库规则没有新增前端测试或运行前端 build；生产静态前端需要下次正常构建更新才能显示卡片，已有动态基础配置字段可使用后端 Schema。未现场启动机器人或执行真实群聊管理命令，未提交推送。
