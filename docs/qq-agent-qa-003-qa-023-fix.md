## QA-003：会话恢复失败未传播

ChatManager.initialize 原先捕获恢复异常后正常返回，MainSystem 因而继续启动。load_all_sessions_from_db 在恢复前及失败后清空缓存，逐条加载还会暴露部分结果。

修复后，初始化记录完整异常并重新抛出；在工作线程中读取完整快照，数据库上下文正常退出后一次性替换 sessions。与创建、身份更新、批量保存共用线程锁。查询、记录转换或事务收尾失败均保留原缓存，故障消除后可重新调用 initialize 恢复。主启动链路收到异常，不启动依赖会话恢复的后台服务。

## QA-023：插件实际启动失败未传播

PluginRuntimeManager.start 原先完成回滚后正常返回，MainSystem 的 gather 无法区分实际启动失败。

修复后，已进入资源启动阶段的异常及取消均执行回滚，再抛出原始异常；清理覆盖已构建的 Supervisor（含尚未成功返回的部分）、文件监听、Platform IO、Hook dispatcher 和已注册配置回调。各回滚步骤的普通异常记录完整堆栈后继续清理，状态通知失败也不覆盖原始启动异常。最终重置 started、Supervisor 引用和回调注册标记。

配置明确禁用或没有插件目录时仍正常跳过；单个插件加载失败的既有隔离机制未改变。本修复不将可选组件跳过一律升级为启动失败，也不改变主程序既有退出清理责任。
